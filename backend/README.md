# Recruitment Management Backend

Recruitment management backend using FastAPI, SQLAlchemy, and PostgreSQL. Database models and lifecycle rules are defined in `app/`; the field-level contract is in `data_dictionary.md`.

Set `DATABASE_URL` in the process environment before creating a database engine. `.env.example` is a template and is not loaded automatically. Do not commit credentials.

Core IDs are generated by the application/data generator, not database defaults. Ground-truth labels are kept out of screening inputs and will be exported separately by the data-generation phase.

## Recruitment API

The API reuses the SQLAlchemy mappings and lifecycle/screening rules in `app/`. Configure `DATABASE_URL` before starting it; the schema must already exist. For a local PostgreSQL database, for example:

```powershell
$env:DATABASE_URL = "postgresql+psycopg://postgres:YOUR_PASSWORD@127.0.0.1:5432/recruitment"
python -c "from app import models; from app.database import Base, get_engine; Base.metadata.create_all(get_engine())"
python -m uvicorn app.main:app --reload
```

The health check is `GET /health`. CORS allows `localhost` and `127.0.0.1` on ports 3000 and 5173 by default; override this with a comma-separated `CORS_ORIGINS` value. Mutations record application/requisition/offer lifecycle events and audit records. Requisition creation includes required-skill screening rules; screening uses only those rules and candidate job-related skills.

Run the API tests from `backend/` with the active project environment:

```powershell
python -m pytest tests -q
```

Tests create an isolated SQLite database and do not require a live PostgreSQL server.

## Synthetic data generation

Run from `backend/` with the project Python environment:

```powershell
python -m app.data_tools --size starter --verify-reproducibility
python -m app.data_tools --size full --verify-reproducibility
```

The generator uses seed `20261022`, the existing SQLAlchemy models, and an in-memory SQLite transaction for schema and relationship validation. It writes deterministic CSVs, a JSON dataset, PostgreSQL-compatible SQL seed statements, separate ground-truth CSV/JSON files, validation reports, and reproducibility checksums to the project-root `generated-data/` directory. The validation report intentionally shows failed checks for injected anomalies; `validation_passed` means every known anomaly was detected at its expected severity and there were no unexpected findings.

Offer responses are deterministic: an offer is accepted only when its salary is at least 90% of the approved salary range above the range minimum and every panelist across both interview rounds returned `strong_yes`. Otherwise the candidate rejects it. A response is recorded seven days after issuance, with the reason in the final `offer_events` row; no response outcome is assigned independently at random.

### Applying the SQL seed to PostgreSQL

Live PostgreSQL validation was not available in the generation environment. To test against a disposable local PostgreSQL database, install PostgreSQL client/server tools and configure local authentication (for example, in the user's PostgreSQL password file). The following PowerShell commands create the schema from the SQLAlchemy mappings, apply the seed, and verify core counts and validated foreign keys. Use only a disposable database because the first command drops the named database.

```powershell
$pgUser = "postgres"
$pgHost = "127.0.0.1"
$pgPort = 5432
$pgDatabase = "recruitment_phase2_test"
$pgUrl = "postgresql://$pgUser@${pgHost}:$pgPort/$pgDatabase"

dropdb --if-exists -h $pgHost -p $pgPort -U $pgUser $pgDatabase
createdb -h $pgHost -p $pgPort -U $pgUser $pgDatabase
$env:DATABASE_URL = "postgresql+psycopg://$pgUser@${pgHost}:$pgPort/$pgDatabase"

Set-Location C:\CandidateWorkspace\backend
python -m pip install "psycopg[binary]>=3.2,<4.0"
python -c "from app import models; from app.database import Base, get_engine; Base.metadata.create_all(get_engine())"
psql $pgUrl -v ON_ERROR_STOP=1 -f ..\generated-data\full_seed.sql
psql $pgUrl -v ON_ERROR_STOP=1 -c @'
SELECT 'departments' AS table_name, COUNT(*) AS row_count FROM departments
UNION ALL SELECT 'skills', COUNT(*) FROM skills
UNION ALL SELECT 'job_requisitions', COUNT(*) FROM job_requisitions
UNION ALL SELECT 'candidates', COUNT(*) FROM candidates
UNION ALL SELECT 'candidate_skills', COUNT(*) FROM candidate_skills
UNION ALL SELECT 'resume_artifacts', COUNT(*) FROM resume_artifacts
UNION ALL SELECT 'screening_rules', COUNT(*) FROM screening_rules
UNION ALL SELECT 'interviewers', COUNT(*) FROM interviewers
UNION ALL SELECT 'interviewer_availability', COUNT(*) FROM interviewer_availability
UNION ALL SELECT 'applications', COUNT(*) FROM applications
UNION ALL SELECT 'interviews', COUNT(*) FROM interviews
UNION ALL SELECT 'interview_panel', COUNT(*) FROM interview_panel
UNION ALL SELECT 'feedback', COUNT(*) FROM feedback
UNION ALL SELECT 'offers', COUNT(*) FROM offers
UNION ALL SELECT 'requisition_events', COUNT(*) FROM requisition_events
UNION ALL SELECT 'application_events', COUNT(*) FROM application_events
UNION ALL SELECT 'offer_events', COUNT(*) FROM offer_events
UNION ALL SELECT 'duplicate_application_attempts', COUNT(*) FROM duplicate_application_attempts
UNION ALL SELECT 'audit_events', COUNT(*) FROM audit_events
UNION ALL SELECT 'exception_records', COUNT(*) FROM exception_records
ORDER BY table_name;
'@
psql $pgUrl -v ON_ERROR_STOP=1 -c "SELECT conname FROM pg_constraint WHERE contype = 'f' AND NOT convalidated;"
```
