# Recruitment Schema Data Dictionary

All timestamps use timezone-aware UTC values. Salary and score amounts use decimal types. IDs are immutable strings generated by the application; the required REQ, CAND, APP, INT, FB, and OFF formats are applied by the data/API layer. Enum values are stored in lowercase. Demographic fields are intentionally excluded from candidate and screening records.

## Core entities

### Department

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `department_id` | string(20) | Yes | Primary key; generated stable ID |
| `name` | string(120) | Yes | Unique, non-empty |
| `description` | text | No | Optional plain text |
| `is_active` | boolean | Yes | Defaults true |
| `created_at`, `updated_at` | timestamptz | Yes | Database timestamps |

### JobRequisition

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `requisition_id` | string(20) | Yes | PK; `REQ-2026-000001` format |
| `department_id` | string(20) | Yes | FK to Department |
| `title` | string(160) | Yes | Non-empty |
| `description` | text | Yes | Role-related description |
| `employment_type` | enum | Yes | `full_time`, `part_time`, `contract`, `temporary` |
| `location` | string(160) | Yes | Work location |
| `salary_min`, `salary_max` | numeric(12,2) | Yes | Currency units; min >= 0 and max >= min |
| `currency` | string(3) | Yes | ISO-style uppercase currency code |
| `headcount` | integer | Yes | Positive; defaults to 1 |
| `status` | enum | Yes | `draft`, `pending_approval`, `open`, `on_hold`, `closed` |
| `created_by` | string(120) | Yes | Requesting actor identifier |
| `approved_by`, `approved_at` | string / timestamptz | No | Required by workflow before opening |
| `opened_at`, `closed_at` | timestamptz | No | Lifecycle timestamps; state changes also recorded as events |
| `created_at` | timestamptz | Yes | Database timestamp |

### Candidate

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `candidate_id` | string(20) | Yes | PK; `CAND-000001` format |
| `full_name` | string(160) | Yes | Synthetic or provided name; non-empty |
| `email` | string(254) | Yes | Unique; validated email format in API |
| `phone` | string(32) | No | Optional contact value |
| `location` | string(160) | No | Optional work location |
| `professional_summary` | text | No | Job-related professional information only |
| `portfolio_url` | string(500) | No | Optional validated URL |
| `created_at` | timestamptz | Yes | Database timestamp |

### Application

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `application_id` | string(80) | Yes | PK; `APP-{requisition_id}-{candidate_id}` |
| `requisition_id` | string(20) | Yes | FK to JobRequisition |
| `candidate_id` | string(20) | Yes | FK to Candidate |
| `status` | enum | Yes | `applied`, `screening`, `interview`, `offer`, `hired`, `rejected`, `withdrawn` |
| `submitted_at` | timestamptz | Yes | Application submission time |
| `screening_score` | numeric(5,2) | No | 0-100; calculated from active screening rules |
| `screening_explanation` | JSON | No | Score components and missing job skills; no ground-truth labels |
| `source` | string(80) | No | Optional sourcing channel |
| `updated_at` | timestamptz | Yes | Database timestamp |
| `(requisition_id, candidate_id)` | composite | Yes | Unique; duplicate submissions are retained in DuplicateApplicationAttempt |

### ResumeArtifact

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `resume_id` | string(24) | Yes | PK; stable generated ID |
| `candidate_id` | string(20) | Yes | FK to Candidate |
| `application_id` | string(80) | No | Optional FK to Application |
| `file_name` | string(255) | Yes | Original display name |
| `storage_uri` | string(1000) | Yes | Storage reference; file bytes are not stored in this row |
| `content_type` | string(120) | Yes | MIME type; PDF extraction supported |
| `sha256` | string(64) | Yes | SHA-256 checksum |
| `extraction_status` | enum | Yes | `uploaded`, `processing`, `processed`, `failed` |
| `extracted_text` | text | No | Extracted text, when available |
| `uploaded_at` | timestamptz | Yes | Database timestamp |

### Skill

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `skill_id` | string(20) | Yes | PK; stable generated ID |
| `name` | string(100) | Yes | Unique, non-empty |
| `category` | string(80) | No | Optional job-related category |
| `is_active` | boolean | Yes | Defaults true |

### CandidateSkill

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `candidate_id` | string(20) | Yes | PK part; FK to Candidate |
| `skill_id` | string(20) | Yes | PK part; FK to Skill |
| `effective_from` | timestamptz | Yes | PK part; starts this skill assessment version |
| `proficiency_level` | smallint | Yes | Integer 1-5 |
| `years_experience` | numeric(5,2) | Yes | Years, >= 0; defaults to 0 |
| `effective_to` | timestamptz | No | Must be later than `effective_from` |

### ScreeningRule

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `screening_rule_id` | string(24) | Yes | PK; stable generated ID |
| `requisition_id` | string(20) | Yes | FK to JobRequisition |
| `skill_id` | string(20) | No | FK to Skill; required for skill-specific rules |
| `rule_type` | enum | Yes | `required_skill`, `weighted_skill`, `min_experience`, `pass_threshold` |
| `criterion_name` | string(100) | Yes | Named job-related criterion |
| `weight` | numeric(5,2) | Yes | Non-negative scoring weight |
| `minimum_proficiency` | smallint | No | Integer 1-5 |
| `minimum_value` | numeric(8,2) | No | Criterion-specific units, such as years or score threshold |
| `effective_from`, `effective_to` | timestamptz | Yes / No | End, when present, must follow start |
| `is_active` | boolean | Yes | Only active, effective rules are applied |

### Interview

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `interview_id` | string(24) | Yes | PK; `INT-2026-000001` format |
| `application_id` | string(80) | Yes | FK to Application |
| `round_number` | integer | Yes | Positive; one interview per application and round |
| `interview_type` | enum | Yes | `phone`, `video`, `onsite`, `technical`, `panel` |
| `starts_at`, `ends_at` | timestamptz | Yes | End later than start; availability checked by service |
| `status` | enum | Yes | `scheduled`, `completed`, `cancelled`, `no_show` |
| `outcome` | enum | No | `advance`, `reject`, `hold`; set after interview |
| `issue_type` | enum | No | Exception classification, not a screening input |

### Interviewer

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `interviewer_id` | string(24) | Yes | PK; stable generated ID |
| `department_id` | string(20) | No | Optional FK to Department |
| `display_name` | string(160) | Yes | Non-empty |
| `email` | string(254) | Yes | Unique; validated email format in API |
| `is_active` | boolean | Yes | Inactive interviewers cannot be scheduled |

### Feedback

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `feedback_id` | string(80) | Yes | PK; `FB-{interview_id}-{interviewer_id}` |
| `interview_id` | string(24) | Yes | FK to Interview and panel membership |
| `interviewer_id` | string(24) | Yes | FK to Interviewer and panel membership |
| `technical_rating`, `communication_rating`, `role_rating` | smallint | Yes | Each integer 1-5 |
| `recommendation` | enum | Yes | `strong_yes`, `yes`, `no`, `strong_no` |
| `comments` | text | No | Structured job-related comments |
| `submitted_at` | timestamptz | Yes | Submission time; one feedback per panelist per interview |

### Offer

| Field | Type | Required | Uniqueness / validation |
|---|---|---:|---|
| `offer_id` | string(24) | Yes | PK; `OFF-2026-000001` format |
| `application_id` | string(80) | Yes | FK to Application |
| `salary` | numeric(12,2) | Yes | Positive; checked against requisition band before approval/issue |
| `currency` | string(3) | Yes | Must match requisition currency |
| `status` | enum | Yes | `pending_approval`, `approved`, `issued`, `accepted`, `declined`, `rejected`, `withdrawn` |
| `created_by` | string(120) | Yes | Offer requester |
| `approved_by`, `approved_at` | string / timestamptz | No | Required before issuing |
| `issued_at`, `responded_at` | timestamptz | No | `responded_at` is the acceptance or rejection response time; pending, approved, and issued offers have no response time. |

For generated data, `rejected` denotes a candidate response after issuance. Its response date is `responded_at`, and its required reason is stored on the matching `OfferEvent` transition. Every approval, issuance, and final response is represented in `offer_events`.

## Supporting tables

| Table | Purpose and constraints |
|---|---|
| `interview_panel` | Bridge table for Interviewer <-> Interview many-to-many; composite PK and FKs. |
| `interviewer_availability` | Interviewer availability windows; FK, positive duration, indexed by interviewer/time. |
| `requisition_events` | Immutable requisition status transitions with actor, reason, and timestamp. |
| `application_events` | Immutable application status transitions with actor, reason, and timestamp. |
| `offer_events` | Immutable offer status transitions with actor, reason, and timestamp. |
| `duplicate_application_attempts` | Preserves a repeated submission without violating the canonical APP ID and unique application rule. |
| `audit_events` | General actor/action/change trace; entity reference is validated by the audit service because it is polymorphic. |
| `exception_records` | Detected issue, source reference, expected decision, observed details, and validation result. Ground-truth labels live in separate generated artifacts. |

## Relationship cardinality

- Department 1:N JobRequisition; Department 1:N Interviewer (optional on Interviewer).
- JobRequisition 1:N Application; Candidate 1:N Application. Together, these are the candidate-to-requisition relationship.
- Candidate 1:N ResumeArtifact; Application 0:N ResumeArtifact.
- Candidate N:M Skill through CandidateSkill; JobRequisition N:M Skill through ScreeningRule.
- Application 1:N Interview and 1:N Offer.
- Interview N:M Interviewer through `interview_panel`; Interview 1:N Feedback, with at most one feedback per panelist.
- Interviewer 1:N InterviewerAvailability.
- Requisition, Application, and Offer each have 1:N status-history events.
